1. 从 b162ca3 的快照和运行清单确定 ZARA2 / Stage 2 / candidate_cost 的实验身份。核对实际工作目录、进程命令行、控制器及恢复入口。使用该试验原有的安全暂停机制，让在途更新在可保存边界结束。若试验已经结束或暂停，直接记录现状。勿按名称批量杀进程，勿使用旧报告中的 PID。原五折队列继续保持 PAUSED_RESUMABLE。
2. 核对最后一次已提交 update、完整 epoch、last、best、Top5 和恢复游标；区分“收到请求时观察到的更新数”“最后保存数”“诊断新增更新数”。保留模型、优化器、调度器、RNG、已有 bank 和原始日志。只有现场确实发生提前停止时，才将原试验记为“按研究决策提前暂停”；自然完成则记录实际停止原因。

二、固定一次成对比较

• 权重选定为新旧各 epoch 1、3、5。第 1 轮交代起点，第 3、5 轮是预先指定的两个主比较轮次。使用真实归档权重 strict-load，不能用接近的轮次代替，也不靠补训重建。缺失某项时保留可用表格，明确哪些结论无法判定。
• 使用已冻结的 ZARA2 官方 train（2681 窗）和 selection_dev（590 窗，其中 127 窗 ≥9 人）、seed 2035、K=20 及各自既有 refined bank。训练集用与候选对应的固定原始视图，关闭随机增广。用窗口 ID、帧、有效行人顺序、单位和候选身份校验对齐。同一 split 内新旧权重逐窗配对。不同 split 单独汇总。
• 复用 4c9eede 中已经核准的端点计分与归档。已有 dev 结果若有足够精度且身份、窗口与分母一致，直接使用；只为缺项运行 eval/inference_mode 的硬配对前向。优先复用仓库的实际 assign 和 gather_candidates。提取第一次 Hungarian 的结果，并记录同次前向加入邻居反馈后的最终结果。真值仅供计分。跳过轨迹桥和 DDIM，H-JADE 只读既有验证日志。

三、计算与核查

对每个窗口，用米制最终位置，分别给原始候选编号 G、初次配对 I、反馈后配对 H 计分。对同一个联合样本先求有效行人的平均误差，再在 20 个联合样本中取最小。最后对窗口等权平均。可按下列伪代码核对轴顺序：

    # goals[k, i, xy] 是按某种配对组织的终点，valid 是场景中的有效行人
    def joint_fde(goals, truth, valid):
        err = l2_norm(goals[:, valid, :] - truth[None, valid, :], axis=-1)
        return err.mean(axis=1).min()

    initial_error = joint_fde(initial_goals, truth, valid)
    final_error   = joint_fde(final_goals, truth, valid)
    feedback_gain = initial_error - final_error        # 正值表示反馈改善
    delta_initial = initial_new - initial_old          # 正值表示新版退步
    delta_final   = final_new - final_old

每个 split、epoch、人数组（全部、≥9人）报告实际窗口数、G/I/H、反馈收益以及新减旧的配对差值。记录逐窗结果，以便复算。同一候选下 G 与逐人最小误差应跨权重不变；单人窗 G=I=H；每窗满足 delta_final = delta_initial − (gain_new − gain_old)。使用仓库原有数值容差，记录最大偏差。任何实质不一致先核对窗口、维度、掩码和候选身份；无法消除的部分标为不可判读。

四、写出唯一结论并结束

以第 3、5 轮的同轮差值为主要依据。预先采用 0.01 m 作为本次决策的工程量级，原始数值全部列出；该量级没有统计显著性含义。先看全部窗口，再用 ≥9 人组检查结论是否反向。不要把训练集与开发集的绝对误差相减来判定过拟合。按下列顺序给出唯一建议：

A. 两轮中，train 和 dev 的 delta_initial 均超过 +0.01 m，密集组也没有实质反向：判为“新代理在训练样本上也出现初次硬配对退步”。恢复旧坐标代理作为后续研究基线；若项目决定再做模型改动，唯一候选是给第一次 Hungarian 的输出增加直接的场景级联合终点监督，沿用旧版可微代理，最终配对监督与邻居反馈保留。报告说明数据只能定位退步发生的环节，尚不能证明这种改法有效。本轮不实施。
B. 两轮 dev 的 delta_initial 均超过 +0.01 m，而两轮 train 均未超过 +0.01 m，且密集组没有实质反向：判为“开发窗口的退步未在固定训练窗口中同样出现”。以旧 v2 为基线，在已有逐窗结果中按录制及人数汇总贡献，说明退步的分布；不据此认定过拟合或增加网络层数。
C. 其他情况，包括方向混合、仅反馈后退步、最新正式 rank1 已经反转或关键身份无法核验：如实报告能够成立的最窄结论，保留现有基线和两套资产，结束这条验证。若最新结果反转，优先进入 C，明确哪些指标、哪个已完成轮次改变了判断。不得通过追加轮次、挑选窗口或更换阈值来形成结论。
